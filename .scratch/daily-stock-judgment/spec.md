# 日次株価売買判断ツール

Status: ready-for-agent

用語はリポジトリ根の `CONTEXT.md` に従う。決定の詳細は [map](map.md) の Decisions so far を正とする。

## Problem Statement

個人投資家として、大引け後にウォッチリストと保有の日本株を眺めても、四本値だけでは「買う／売る／様子見」の目安を毎回自分で整理するのが負担である。発注まではしたくないが、その日の方向感と短い根拠を一覧で見たい。

## Solution

自分専用の localhost Web で、ウォッチリストと保有を管理し、大引け後に手動で判断ランを回す。各銘柄についてスコア（-100〜+100）・ラベル（買う／売る／様子見）・短い理由を一覧できる。株価は日次四本値と出来高（yfinance）、判断のスコアと理由はローカルのエージェント CLI 経由の汎用 LLM、ラベルは固定閾値でシステムが付与する。成功した判断は履歴に残り、過去日の一覧も見られる。

## User Stories

1. As a 個人ユーザー, I want ウォッチリストに日本株ティッカーを追加する, so that 保有していなくても監視対象にできる
2. As a 個人ユーザー, I want ウォッチリストから銘柄を削除する, so that もう見ない銘柄を外せる
3. As a 個人ユーザー, I want 保有銘柄を登録する, so that 売るラベルの対象にできる
4. As a 個人ユーザー, I want 保有を解除する, so that 売った銘柄を保有一覧から外せる
5. As a 個人ユーザー, I want 保有に数量を任意で記録する, so that 必要ならメモできるが必須にはしたくない
6. As a 個人ユーザー, I want ウォッチと保有を画面から追加・変更・削除する, so that 設定ファイルを手編集しなくてもよい
7. As a 個人ユーザー, I want データがローカルの SQLite に保存される, so that 自分のマシンだけで完結する
8. As a 個人ユーザー, I want localhost で判断一覧を見る, so that クラウド認証なしで日次確認できる
9. As a 個人ユーザー, I want 大引け後に手動で判断ランを実行する, so that 好きなタイミングで一覧を更新できる
10. As a 個人ユーザー, I want 推奨時刻（営業日 16:00〜21:00 JST、目安 18:00）を仕様として知る, so that 遅延データの影響を避けやすい
11. As a 個人ユーザー, I want 休場日には新規の判断が作られない, so that 無い取引日を当日扱いにしない
12. As a 個人ユーザー, I want 半日取引でも当日バーが取れれば通常どおり判断される, so that 短縮取引日も使える
13. As a 個人ユーザー, I want 同じ日に判断ランを再実行できる, so that データ未着のあとにやり直せる
14. As a 個人ユーザー, I want OS のスケジューラで任意に自動実行できる, so that 必須機能にしなくても便利に回せる
15. As a 個人ユーザー, I want 登録銘柄の日足四本値と出来高が取得される, so that LLM が価格観察できる
16. As a 個人ユーザー, I want LLM に直近最大60営業日分の bars が渡される, so that 短期の水準・変化を根拠にできる
17. As a 個人ユーザー, I want 履歴が60営業日に満たない銘柄でも取れた分だけで判断される, so that 新規上場なども止めない
18. As a 個人ユーザー, I want 各銘柄についてスコアを得る, so that 買い寄り／売り寄りの強さが分かる
19. As a 個人ユーザー, I want 各銘柄について短い理由を得る, so that なぜその方向かをその場で確認できる
20. As a 個人ユーザー, I want 理由に終値の水準か変化への言及が含まれる, so that チャートや数字と突き合わせられる
21. As a 個人ユーザー, I want 理由がおおよそ200文字以内である, so that 一覧で読める
22. As a 個人ユーザー, I want 理由がラベル語や発注煽りを含まない, so that 行動区分と混線しない
23. As a 個人ユーザー, I want スコアからラベルが自動で付く, so that LLM にラベルを任せず一貫する
24. As a 個人ユーザー, I want スコア ≥ +50 なら買うと出る, so that 買い寄りがはっきり分かる
25. As a 個人ユーザー, I want スコア ≤ −50 かつ保有中なら売ると出る, so that 保有の手仕舞い目安になる
26. As a 個人ユーザー, I want 未保有で売り寄りでも様子見になる, so that 持っていない銘柄に売るが出ない
27. As a 個人ユーザー, I want 閾値の外側は様子見になる, so that 弱い方向では動かない判断になる
28. As a 個人ユーザー, I want 買うラベルがウォッチにも保有にも付く, so that 新規も積み増しも同じ一覧で見られる
29. As a 個人ユーザー, I want 判断は提示までで発注や数量提案がない, so that ツールが売買執行に踏み込まない
30. As a 個人ユーザー, I want 一部銘柄が失敗しても他銘柄の判断は一覧に出る, so that 全体が無駄にならない
31. As a 個人ユーザー, I want 当日バー未着の銘柄が「データ未着」と分かる, so that あとで再実行できる
32. As a 個人ユーザー, I want 存在しない／空の銘柄が「取得不可」と分かる, so that ティッカー誤りに気づける
33. As a 個人ユーザー, I want LLM 失敗や制約不合格が「判断失敗」と分かる, so that 再実行や銘柄見直しができる
34. As a 個人ユーザー, I want 失敗行にスコア・ラベル・理由が出ない, so that 不完全な判断を信じない
35. As a 個人ユーザー, I want 成功した判断だけが履歴に残る, so that 過去日には確定結果だけが並ぶ
36. As a 個人ユーザー, I want 過去日の判断一覧を見られる, so that 前日以前の目安を振り返れる
37. As a 個人ユーザー, I want 同日再実行で銘柄×判断日が上書きされる, so that 最新の成功結果だけが残る
38. As a 個人ユーザー, I want 履歴が自動削除されない, so that 長く手元に残せる
39. As a 個人ユーザー, I want Cursor CLI や Claude Code などローカルエージェント CLI で判断生成できる, so that 特定クラウド API 直呼びに縛られない
40. As a 個人ユーザー, I want アプリ内にプロバイダ切替 UI がない, so that どの CLI で回すかは運用に任せられる
41. As a 個人ユーザー, I want コスト上限が仕様や画面に出てこない, so that 予算管理をサブスク側に任せられる

## Implementation Decisions

### 全体構成

- localhost の自分専用 Web（閲覧・ウォッチ／保有 CRUD・判断一覧・過去日一覧）と、手動起動の日次判断ランナーを持つ
- 正本ストアは SQLite（ウォッチリスト、保有、成功した判断の履歴）
- 相場データは yfinance の日本株日足（`.T`）。価格別出来高やチャート画像は使わない
- 判断エンジン本体は汎用 LLM（専用学習モデルなし）。呼び出しはローカルのエージェント CLI 経由。製品名・モデルスナップショットは仕様に固定しない
- Cloudflare Tunnel / Access は使わない

### 日次判断ランナー（テストの主 seam）

- 入力: 判断日（`as_of`）、対象銘柄（ウォッチと保有の和。保有フラグ付き）
- 出力: 銘柄ごとの結果（成功: スコア・ラベル・理由／失敗: 区分のみ）
- 休場日（または当日バーが市場全体として無い日）は新規判断を作らない
- 銘柄ごとに独立して処理し、部分成功を許す
- 相場取得とエージェント CLI 呼び出しはポート／アダプタとして差し替え可能にする（テストではフェイク）

### ラベル付与（システム）

- LLM はラベルを出さない
- スコア ≥ +50 → 買う
- スコア ≤ −50 → 売る（保有時のみ。未保有は様子見）
- 上記以外 → 様子見
- ±50 ちょうどは買う／売る側

### LLM 入出力

- 1銘柄＝1回
- 入力: `ticker`, `as_of`, `is_holding`, `bars`（最大60営業日の `date/open/high/low/close/volume`）。数量・銘柄名・ニュース等は渡さない
- 出力: `ticker`, `score`（整数 -100〜+100）, `reason`。`label` なし
- プロンプト: 固定指示ブロック（役割、入力以外不使用、理由要件、JSON のみ、ラベル禁止）＋入力 JSON
- 事後検証: JSON／score 範囲、reason おおよそ200字以内、ラベル語不使用、スコア符号と理由向きの明らかな食い違い。不合格は再生成1回、ダメなら `判断失敗`
- 呼び出し失敗も同じ銘柄で最大1回リトライ、ダメなら `判断失敗`

### 理由要件（プロンプトに載せる内容）

- 観察必須（終値まわりの水準か変化を1つ以上）。解釈は任意で短くてよい。出来高言及は任意
- 禁止: 入力にない情報の断定、数字も水準もない雰囲気だけ、発注を促す言い回し
- 理由本文にラベル語（買う／売る／様子見）を使わない

### データ欠落

- 当日バー未着（遅延っぽい）: 取得リトライ最大2回 → なお無ければ `データ未着`。捏造しない
- 銘柄空／不存在: リトライせず `取得不可`
- 失敗区分の表示は `データ未着` / `取得不可` / `判断失敗` のみ

### 履歴

- 成功した判断のみ SQLite に保存（スコア・ラベル・理由）
- 銘柄×判断日で上書き。版は残さない。自動削除なし
- UI 必須は過去日の一覧閲覧まで。成績グラフ等は不要

### 運用メモ（仕様に上限や製品固定は書かない）

- 実行は手動が正。OS スケジューラ自動は任意
- コスト上限は仕様外（CLI／サブスクの運用任せ）。品質遵守をコストより優先

## Testing Decisions

- 良いテストは、日次判断ランナー境界から見える外部振る舞いだけを検証する。SQLite スキーマや CLI 引数の内部詳細には依存しない
- 主にテストするモジュール: 日次判断ランナー（上記 seam）
- 差し替え: 相場データ取得（バー未着／空銘柄／正常系列）、エージェント CLI（正常 JSON／不正 JSON／符号不一致理由／タイムアウト）
- 検証したい振る舞い例:
  - 正常系でスコア・ラベル閾値・理由が結果に載る
  - 未保有かつスコア ≤ −50 は様子見
  - 一部銘柄失敗でも他は成功（部分成功）
  - データ未着・取得不可・判断失敗の区分
  - 成功のみが永続化され、同日再実行で上書きされる
  - 休場日は新規判断なし
- リポジトリに既存アプリ／テストの先行事例はない（グリーンフィールド）。最初のテストスイートはこの seam を中心に置く

## Out of Scope

- 発注連携・推奨数量・自動売買
- 専用の学習モデルや手書きテクニカルルールを本体にする方式
- 複数ユーザー・共有利用
- 日本株以外の市場、市場全体からの候補出し
- ニュース・財務・板情報・価格別出来高・チャート画像などの非・日足数値データ
- 寄り付き前・場中の判断
- Cloudflare Tunnel / Access
- 事後の当たり外れ検証（バックテスト・勝率集計等）
- アプリ内の LLM プロバイダ切替 UI
- 仕様上のコスト上限・予算キャップ
- 成績グラフや高度な振り返り UI（過去日一覧より先）
