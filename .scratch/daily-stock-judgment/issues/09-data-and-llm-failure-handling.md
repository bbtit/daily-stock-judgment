# データ欠落とLLM失敗時の扱いは何か

Type: grilling
Status: resolved

## Question

yfinance で当日バーが欠ける・銘柄が空になる、または LLM 呼び出しが失敗したとき、仕様上どうするか。リトライ、スキップ、エラー表示、一覧の部分成功は許すか。

（背景: [yfinanceは日本株の日足取得に足りるか](01-yfinance-japan-daily-ohlcv.md) の調査で、欠測とリトライが運用上の論点として上がった。）

## Answer

**部分成功を許す。** 成功した銘柄は通常どおり一覧に載せ、失敗した銘柄だけエラーとする。全体を一括失敗にしない。

### データ

- **当日バー未着（遅延っぽい）**: 取得リトライ最大2回。それでも無ければ判断せず区分 `データ未着`（手動再実行待ち）。捏造しない
- **銘柄が空／存在しない**: リトライせず区分 `取得不可`。過去バーで当日判断を作らない
- **休場**: [大引け後ジョブの時刻と休場日はどうするか](07-after-close-schedule.md) どおり新規判断なし（失敗扱いにもしない）

### LLM

- **呼び出し失敗**（CLI 落ち・タイムアウト等）: 同じ銘柄で最大1回リトライ。ダメなら区分 `判断失敗`
- **スキーマ／理由制約不合格**: 再生成1回（[短い理由に必須の要素は何か](04-reason-requirements.md) / [LLMの入出力スキーマとプロンプト骨子は何か](10-llm-io-schema-prompt.md)）。ダメなら `判断失敗`

### 表示

失敗銘柄は短い区分のみ（`データ未着` / `取得不可` / `判断失敗`）。スコア・ラベル・理由は出さない。詳細はローカルログに残してよい。同じ日の手動再実行は常に可。
