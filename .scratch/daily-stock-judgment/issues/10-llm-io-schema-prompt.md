# LLMの入出力スキーマとプロンプト骨子は何か

Type: grilling
Status: resolved

## Question

ローカルのエージェント CLI 経由で渡す入力・返す出力のスキーマと、プロンプトの骨子をどうするか。スコアと理由のフィールド、理由要件（観察必須・禁止表現・約200文字・ラベル語禁止・スコア符号との整合）をどう載せて守らせるか。

## Answer

### 呼び出し単位

1銘柄＝1回。

### 出力（LLM）

```json
{ "ticker": "7203.T", "score": 62, "reason": "…" }
```

- `score`: 整数、-100〜+100
- `reason`: 文字列（理由要件は [短い理由に必須の要素は何か](04-reason-requirements.md)）
- `label` は含めない（システムが閾値で付与）

### 入力（LLMへ渡す）

- `ticker`（例: `7203.T`）
- `as_of`（判断日、YYYY-MM-DD）
- `is_holding`（boolean。数量は渡さない）
- `bars`: 直近最大60営業日の日足（`date`, `open`, `high`, `low`, `close`, `volume`）

価格別出来高・日足チャート画像は渡さない。銘柄名やニュース等の付帯情報も渡さない。

### 制約の守らせ方

プロンプトに要件を明記し、システムが事後検証する。最低限: JSON形と score 範囲、reason 長さ（約200字以内）、ラベル語不使用、スコア符号と理由の向きの明らかな食い違い。不合格は再生成1回、なおダメならその銘柄はエラー。

### プロンプト骨子

1. **固定の指示ブロック**: 役割／入力以外不使用／理由要件／出力は指定 JSON のみ／ラベルを出さない
2. **入力 JSON**: 上記1銘柄分

CLI 製品ごとのラップは運用側。仕様が固定するのはこの中身。
